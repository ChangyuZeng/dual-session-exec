# 双会话执行（luna-exec 兼容入口）

新运行使用同级安装的 [dual-session-exec 通用技能](../dual-session-exec/SKILL.md)。先完整读取该入口，按它导航当前角色所需引用；助手路径均相对于 **dual-session-exec 的实际技能目录**，不混用本目录的旧助手。

用户分别选择主会话和子会话的模型、思考强度，不再固定 Luna/max。未指定字段沿用该侧宿主默认；显式选择不受支持时报告限制，不静默替换。主会话保留用户控制，回报消息永不覆盖它的模型。

维护本技能或完善未批准计划时直接处理，不创建聊天、子代理或自动化。已有用户选择和授权优先，不因读取旧示例恢复默认值。

## 继续已有旧运行

先定位原 contract.md、session.json、state.json、真实运行/作业身份和未消费指导。旧契约已绑定本目录的执行侧入口，或 session 没有 session_version=2 时，继续原运行协议：

- 执行侧读 [原执行侧入口](references/executor.md)。
- 主侧按需读 [原监督协议](references/supervision.md)、[原模式与恢复协议](references/goal-mode.md)、[原高效验收协议](references/efficient-review.md)。
- 继续使用本目录原 scripts、真实 threadId/run_id、既有预算和停止条件，不创建替代执行者、不自动加入 v2 或新模式。
- 用户明确修改模型时，先暂停相关写入并核查作业，再更新原格式中的对应角色最新授权、失效旧运行确认，用真实宿主控制恢复同一身份并验证新轮次。主侧回报仍不传模型覆盖；不能追认旧轮次为新模型。
- 旧文档中的固定默认只解释原运行语义，不能覆盖用户最新选择，也不作为新运行默认。未明确授权修复运行时，不向其他已有聊天发送维护通知。

原文件保留用于兼容和审计。新通用技能缺失时报告缺少的 sibling 路径，先完成可独立的准备；不要退回固定模型启动新执行。
