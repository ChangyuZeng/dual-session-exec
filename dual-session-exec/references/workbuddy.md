# WorkBuddy 适配

本地客户端导入与开放平台上架分别验证。2026-10-27 在腾讯 WorkBuddy 5.8.3 的本地上传入口，通用 SKILL.md 的 name/description 格式可以导入并启用；它不要求市场上架那组展示字段。市场包仍按开放平台当前文档单独构建。不要把解析/启用成功当作自动协作实测通过。

## 选择真实后端

当前会话可用工具的预检记录包括 Agent、SendMessage、TaskOutput、TaskStop。它们是受管子代理接口，不是 Codex 独立聊天接口；没有创建/定向恢复原生聊天工具时，不使用 create_thread 或 send_message_to_thread。以当前注入 schema 为准，预检清单不代替实际调用回执。

Agent 的 model 可接受模型 ID/别名或宿主路由。当前预检见到 default/lite/reasoning，default 为宿主默认解析，可能继承主会话；lite/reasoning 是模型路由，不是保证的实际型号或思考强度。用户不指定时允许默认，不为追求两侧不同而擅自覆盖。

当前预检未见独立 effort/thinking 参数。无该字段就记录 unsupported 并省略；用户显式要求 high/max 等控制时先说明能力缺口，不以 reasoning 路由模拟它。主侧型号由宿主界面控制；界面标签、工具请求与实际后端型号分开记录，可观察不到时为 unknown。不改全局配置或应用数据库来补能力。

## 身份、回传和恢复

启动唯一 Agent，使用当前接口支持的 name/身份字段并保存真实返回的 agent ID。需要后台通信时按该宿主要求登记唯一名称；若接口要求团队注册，仅创建本轮隔离团队和一个执行者，不加入既有团队或广播。创建/投递结果不明先查原记录，不能重建执行者。

命名团队成员返回的 `name@team`、后台 task_id 和普通前台调用返回的 `agent-UUID` 分别记录，不假定它们可互换用于 resume。当前 5.8.3 测试中，命名后台调用返回创建成功后，界面显示已中断，TaskOutput 查无任务；中断原因 unknown。将其复合 ID 传给前台 resume 虽执行了只读检查，却返回不同 agent ID，未证明原身份或历史已恢复。恢复参数被接受不等于原身份找到；核对返回身份与既有上下文，缺乏连续性证据就停止依赖项。前台原生返回能满足交接时，无需为单个执行者额外建立命名团队。

当前版本单执行者可先采用前台 Agent，并将其原生返回的 `agent-UUID` 用于后续 resume。本次前台途径已实测同一 handle、同一原生子会话和历史连续性，实现、自测、主侧验收与一次受控返工闭环通过；实现和返工分别请求 DeepSeek-V4.1-Flash、MiniMax-M3.1-Flash，参数被接受，实际后端型号仍 unknown。这个结果不证明命名后台途径、SendMessage 或独立强度控制已通过；其他版本仍核对当前能力。

异步执行侧通过 SendMessage 向当前主代理回传，父侧按工具返回的真实名称/身份寻址；本次预检描述中的 main 为当前主代理角色地址，不是原生聊天 threadId。前台 Agent 的实际调用结果可以作为原生回传回执，不能只凭执行者的 final 文本声称已送达。必要时由父侧用 TaskOutput 获取后台结果，发送、收到和处理分别保存证据。

当前前台测试中，父侧 Agent 工具结果只包含子侧最后一条 final，未包含其先前的普通 assistant 消息。就绪事实、身份、证据路径与写入暂停声明须放入最后回传正文。若必要信息缺失，先核对该次子记录中可公开的消息与工具回执；保留最初的缺证停止记录，再依据新增原生证据继续，不把中间消息未透出误判为上下文已丢失。

Agent.resume 若当前 schema 支持，复用原 agent ID 继续；是否会保留身份、是否支持恢复时变更 model，须用实际回执核对，不能把参数存在当作已经切换。保留 run_id/request_id、契约、工作目录和同问题的一次返工额度。子代理不调用 Codex 消息参数助手；`scripts/message_args.py` 会拒绝非 Codex adapter，这不是需要绕过的错误。

主侧在活动轮次内收取前台结果或使用宿主等待后台完成；结束该轮前落实真实唤醒或用户恢复安排。不要仅凭创建回执 final 声称“正在执行，收到后继续”。后台生命周期和消息投递未经实测时保持未确认。

## 状态与收尾

契约选一个权威工作流：使用本包 state.json 时，宿主任务卡只作展示索引，不能另建一套漂移的验收清单。必要更新用角色专属助手，--input 的字段直接放 JSON 根层。父侧独立审查、返工及退出标准继续适用。

真实空闲/退出、后台作业和本轮团队资源各自核查。TaskStop 只用于对应本轮仍需停止的任务；不为了确认结束恢复已 idle 的执行者。没有持久目标工具时仅 standard，不用定时任务或文件模拟 goal。客户端导入、当前会话 schema、实际受管子代理运行和市场审核通过是不同层面的结果，分别报告。
