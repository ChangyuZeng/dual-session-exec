# 双会话执行

用当前主会话规划、协调并独立验收，由一个子会话实现和自测。用户分别选择两侧模型和思考强度，不绑定厂商或模型。子会话可以是独立聊天或宿主允许的子代理；一个运行只绑定一个执行身份。

支持读取 SKILL.md 的 agent；自动协作需要宿主会话工具，否则使用用户中转。可选脚本需要 Python 3.11+，状态锁和本地作业守护需要 POSIX。

维护技能、讨论方案或补全未批准计划时直接处理，不启动执行。用户只在本会话批准工作，不代表授权向任意其他聊天发消息；先按宿主规则确认创建与通信权限。使用用户语言交流，代码、命令和原始日志保留原文。

## 1. 选择配置和实际协作方式

先读 [宿主适配与模型选择](references/adapters.md)，检查当前实际工具及模型能力，再选择：

- **原生双会话**：可创建、定向恢复并检查同一子会话，且能可靠交接。
- **受管子代理**：宿主允许委派，并提供持久身份、收取结果和所需的模型控制。明确说明其生命周期限制。
- **用户中转**：缺少自动通信或必要权限时，生成启动包和差异消息，由用户在两个聊天间传递。不假装已创建、已发送或可自动恢复。

用一行列出 `主：模型 / 强度；子：模型 / 强度；协作方式；standard 或 goal`。尊重用户已有选择。缺省采用各自宿主默认，写明“沿用宿主默认，实际未确认”；不要从另一侧记录复制字段来填缺省。宿主自身的子代理默认若继承主侧，按真实默认记录，不能称为已独立指定。用户需要选择但未给值时，展示当前可用选项后补齐；不重复询问已经确定的设置。

`inherit` 表示不向宿主传该覆盖项，`unsupported` 表示宿主没有该控制能力；两者在记录中分别是 null 和能力说明，不作为模型 ID 或强度值传入 API。思考强度采用宿主原生值；不同提供商的 high/max/token budget 不自动互换。显式选择不可用或当前主会话无法切换时，先报告具体限制及所需操作，暂停依赖该选择的执行，不能降级或声称已经切换。

请求配置和实际运行证据分别记录。主会话模型切换只用宿主真实控制或用户界面；子会话回报永不携带主会话模型覆盖。提示词、技能 frontmatter、配置文件和 UI 标签不能证明一次运行用了某模型。

## 2. 冻结契约与唯一身份

按 [通用执行协议](references/protocol.md) 写本轮 `contract.md`，保留批准计划版本、实际 cwd、读写范围、输入版本、交付与验收标准、预算和退出控制、原审批点与停止条件。拆成最少的可复用步骤，为每项指定稳定 ID、依赖和证据位置；不将必须项降为可选。

同目录保存 `session.json`（主会话维护身份/配置）、`state.json`（唯一待办及进展）和原始证据。开始前可用 [session_config.py](scripts/session_config.py) 初始化两侧配置；它只记账，不切换模型或启动会话。没有 Python 时按通用协议维护等价记录，不能丢失必要字段和守卫。

创建前记录 creating 及可核查请求，取得真实执行 ID 后再绑定；异步占位 ID 不能用于通信。结果未知先查原创建，不创建第二个执行者。核对实际 cwd、脏改动、输入访问和共享路径；隔离目录不保证包含未提交输入。不能访问时修正交接位置，不绕过权限或复制整个项目。

把完整契约和 [执行侧入口](references/executor-portable.md) 的实际可读路径交给子会话。它报告就绪、身份、路径与可得的模型证据；主会话绑定真实身份、检查显式配置已满足后才发开始指令。此后复用同一 run_id、执行身份和目录，后续只传版本与差异。

## 3. 推进、交接与接管

已授权的连续步骤自动推进，不把每个检查点变成额外审批。工作、等待和失败写入同一待办；完成须有证据且依赖通过。恢复先查原作业、检查点及输入依赖，避免重复启动。

必需审查、求助、交付和外部等待交接均保存一份 `run_id/request_id + 契约版本 + 条目/阶段 + 差异 + 证据路径 + 所需决定`。原生通信保留真实投递回执，按宿主区分提交、送达和处理；用户中转标为 awaiting_user_relay，接收前不能写成已送达。final、状态文件和过去的等待不是投递证明。同一事件去重，不互发确认消息。

活动主会话使用宿主的事件或有游标的等待；超时不代表失败。长作业由真实 runner/调度器守护。主会话结束活动等待前落实宿主支持的唤醒安排或用户恢复安排，记录回执；文件里的期限不会唤醒模型。未配置自动恢复时如实说明边界。

保留原预算和停止条件。局部排障默认两种有依据的方法失败或 15 分钟无进展即交回，用户更早阈值优先。仅根因、局部补丁和复验明确时，主会话可批准同一 issue 一次 `worker_retry`；再次失败、跨模块诊断或重设计改为 `parent_takeover`。阶段放行用 `continue`，不能重置技术返工次数。主会话接管前暂停子会话对应写入并核查后台作业；接管后子会话仅做指定验证。

## 4. 独立验收与退出

子会话冻结稳定版本、完成自测并交付；主会话按批准标准查看原始证据并独立验证，一次合并当前可判断的必修项与建议。可用 [review_receipt.py](scripts/review_receipt.py) 封存内容/依赖指纹；程序回执和子会话自述不能代替真实审查。依赖变化或新反证使相关验收失效，原计划要求的集成检查仍须执行。

新运行默认 standard。goal 仅在本轮明确选择且宿主确有持久目标工具时使用；不能用 JSON 字段模拟真实目标。goal 须真实关闭并核实，standard 不为确认结束唤醒空闲执行者。

必需项验收通过、可选项按批准分支结案、执行写入暂停、后台作业已处理、实际目标/唤醒安排收尾后才 accepted。取消记 cancelled，预算耗尽不冒充完成，负结果按原标准如实结案。不自动归档会话。

交付说明完成/未完成项、实际目录、验证及原始证据、偏差、两侧请求配置与实际确认状态、已知用量。缺失用量写 unknown，未经对照不声称固定节省比例。

Codex 桌面工具存在时才读 [Codex 适配](references/codex.md)；WorkBuddy 的 Agent/SendMessage 工具存在时读 [WorkBuddy 适配](references/workbuddy.md)。其他 agent 按通用能力映射，不套用这些专用接口。脚本不会代替宿主的权限、模型控制、通信、定时器或进程收尾。
